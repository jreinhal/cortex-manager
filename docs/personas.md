# Personas and Jobs-to-be-Done

This document captures the primary personas for CORTEX and the jobs they hire it to do.

## Data Engineer
Primary jobs-to-be-done:
- When I need to standardize data pipeline reviews, I want a repeatable audit plan so I can reduce defects before production.
- When I add a new repository, I want CORTEX to classify and index it automatically so I can reuse it in future audits.

Pain points:
- Inconsistent documentation and tribal knowledge
- High effort to onboard new team members

Success metrics:
- Faster review cycles
- Fewer production regressions

## AI/ML Scientist
Primary jobs-to-be-done:
- When I evaluate model-related changes, I want a structured rubric so I can compare runs and track regression risk.
- When I compare retrieval quality, I want precision/recall/MRR metrics so I can tune the knowledge base.

Pain points:
- Ad hoc evaluation criteria
- Hard to reproduce previous results

Success metrics:
- Repeatable evaluations
- Clear experiment history

## Software Engineer
Primary jobs-to-be-done:
- When I need a code review or refactor plan, I want a flight plan that points to exact files so I can move quickly.
- When I onboard to a large repo, I want a curated knowledge base so I can understand architecture decisions faster.

Pain points:
- Context switching between docs, repos, and prompts
- Limited traceability of AI decisions

Success metrics:
- Reduced time to first productive change
- Higher-quality, auditable plans
